# The Role of Interrupt Signals
An interrupt is an electrical signal generated by hardware circuits in and out
of the CPU that alters the sequence of instructions executed by the processor.
- Synchronous Interrupts: Produced by the CPU control unit. Only issued after
terminating the execution of an instruction
- Asynchronous Interrupts: Generated by other hardware at arbitrary times

Intel microprocessor manuals desginate synchronous interrupts as execptions and
async interrupts as interrupts. Interrupts are issued by I/O devices and
timers. Execptions are programming errors or anomalous conditions that needs to
be handled by the kernel.

When an interrupt is fired, the CPU stops what it is doing and switches to a
new control flow. It first saves the current program state such as registers in
the kernel mode stack and moving the program counter to an address related to
the interrupt type. It is like a process context switch but is different in
that the code executed by an interrupt or execption handler is not a process.
It runs at the expense of the process that was running when the interrupt
occured and it is also lighter to set up and tear down.

Interrupt handling must follow several constraints
- Interrupts can happen at any time and the kernel wants to deal with it as
fast as possible. Inetrrupt handling can be divided into a critical urgent part
that needs to be excuted right away when an interrupt is delivered and a
deferrable part that can be done later.
- Interrupts can happen when the kernel is already dealing with an interrupt.
This should be allowed as much as possible to keep the I/O devices busy.
Interrupt handlers should thus be executed in a nested manner
- Some critical regions exist where interrupts must be disabled. These critical
regions need to be minimized
